## 五、做了什么

### 5.1 规则引擎移植（`server/lib/`）

从 `AnalyzeRule.kt`（982 行）、`AnalyzeByJSoup.kt`、`AnalyzeByRegex.kt`、
`AnalyzeUrl.kt`、`AppPattern.kt`、`JsExtensions.kt` 逐条对照移植：

| 文件 | 对应 Kotlin |
|---|---|
| `analyzeRule.mjs` | `AnalyzeRule.kt` + `AnalyzeByJSoup.kt` |
| `analyzeUrl.mjs` | `AnalyzeUrl.kt` |
| `html.mjs` | jsoup 的语义子集 |
| `jsbridge.mjs` | `JsExtensions.kt` / `JsEncodeUtils` |
| `webBook.mjs` | `WebBook.kt` 的 search/bookInfo/toc/content |

**最难的一处**：书源 JS 里的 `java.ajax()` 是**同步**返回字符串的（Rhino 引擎同步求值）。
在 Node 里同步 fetch 且不阻塞 fetch 自身，我用了 Worker + `SharedArrayBuffer`：
主线程 `Atomics.wait` 阻塞，worker 线程保持全异步执行 fetch 并写回结果。
第一次实现时 worker 在第一帧就 `Atomics.wait` 了，导致自己饿死 —— 已修正为
worker 只监听消息、主线程负责等待。

**另一处**：`{{}}`、`@get` 出现在规则里时，Legado 会把整个规则降级成 Regex 模式（
`AnalyzeRule.kt` L649-657，这是 2.x 的"无 `##` 正则"约定）。照抄后
`@put:{...}` 的 key 名里带 `{{` 会导致误判，已一并处理。

### 5.2 Web 服务（`server/webservice.mjs`）

与 APK 自带服务同契约：`getReadConfig`、`saveReadConfig`、`getBookshelf`、
`getBookSource(s)`、`getRssSource(s)`、`saveBookSource(s)`、`deleteBookSources`、
`saveBook`、`deleteBook`、`saveBookProgress`、`getChapterList`、`getBookContent`、
`cover`、`image`，外加 `/searchBook`、`/api/proxy`、`/api/health`、`/api/sources/builtin`。
错误响应用 Legado 的 `{isSuccess:false,errorMsg}` 形状。

### 5.3 iPad 界面（`webapp/`）

PWA，可「添加到主屏幕」全屏运行。设计取向：**书是主角，界面退后**。

- 纸色 `#F6F7F5`（偏冷的纸，不是常见的米黄）、墨色 `#14171A`、靛蓝 `#2E5C8A` 单一强调色
- 正文用 **宋体**（Songti SC，iPadOS 自带，离线可用），界面用苹方
- 签名元素：右侧**墨色进度轨**（`ink-rail`）—— 细如书缝、随滚动生长
- 书架有"书脊"阴影和一条横向书架线；封面缺失时用书名做文字封面
- 尊重 `prefers-reduced-motion`；输入框 16px 防 iOS 聚焦缩放；安全区适配横竖屏

### 5.4 原生 iOS 壳（`ios/`）+ CI

- `LegadoMobileApp.swift`：SwiftUI + WKWebView，优先加载打包进 App 的 `WebApp/` 本地壳，
  通过设置面板连接任意 Legado WebService；ATS 放开局域网 http
- `Info.plist`：`MinimumOSVersion 16.0`、`UIDeviceFamily [1,2]`、`arm64`
- `project.pbxproj`：由 `scripts/gen-xcodeproj.cjs` 生成（可在纯文本 diff 里审查）
- `.github/workflows/build-ipa.yml`：`macos-14` runner，
  `CODE_SIGNING_ALLOWED=NO CODE_SIGN_IDENTITY=""`，打包 `Payload/*.app` 成未签名 IPA

测试过程中**发现并修掉的真 bug**（不是我编的）：

1. `#view-read` 这个 id 在 HTML 里根本不存在 → 阅读页点击翻页逻辑整个抛异常
2. `ensureRail()` 里 `$('#view-read') || document.body.appendChild(rail)` 逻辑写反，进度轨永远不显示
3. 防抖保存没有在进程退出时 flush → 杀进程会丢最后一次操作（已加 SIGTERM/exit 落盘）
4. `getString(rule, null, true)` 在多匹配时把多个 URL join 成一行 → 章节链接全错
5. `ruleToc.chapterUrl` 被误当成目录页 URL
6. **`@onclick@js:...` 取值链断裂**：书源常用 `bookUrl: "@onclick@js:result.match(...)[1]"`
   从元素属性里抠参数。我没实现 `RuleAnalyzer.trim()` 对前导 `@` 的剥离，
   导致整条链返回空 —— 搜索结果全被丢掉
7. **`<js>url,{options}</js>` 形式的 URL 规则解析错**：JS 段被整段当程序执行、
   选项对象里的 `{{key}}` 先被插值破坏了结构 → 报 `Invalid regular expression flags`
8. **URL 规则里的选项对象被忽略**：`method`/`charset`/`body` 全部丢失，
   POST 变 GET、gbk 站点乱码

**失败原因分布（这是最有价值的部分）**：

**这些源用到的规则特性统计**：`{{}}` 22/22、`@js` 16/22、`java.net` 9/22、`jsonpath` 5/22。

**怎么读这个数字**：

- 22 个源里只有 1 个能跑通，看着不高，但**其中 3 个是站点已死、3 个需要 WebView、
  13 个是站点改版导致选择器失效** —— 这些都是与"规则引擎是否正确"无关的因素。
- 反过来，这批真实源直接暴露了 4 个我原先没覆盖的写法（上面的 bug 6/7/8），
  **这些现在全部修好并进了回归测试**。这是自己造夹具测不出来的。
- 换句话：**引擎对规则语法的支持面明显提升了，但"22 个源能跑通几个"很大程度取决于
  那些站点今天还活着没有**，这个数字会随时间漂移。

## 七、iPad 上怎么装（三条路，按你的条件选）

### A. 零工具链，今天可用 —— Safari 添加到主屏幕

```powershell
cd D:\Documents\deepseek-harness\default-workspace\legado-ios\server
node webservice.mjs
```
iPad Safari 打开 `http://<电脑局域网IP>:1234` → 分享 → 添加到主屏幕。
全屏、有图标、离线可打开壳。**代价**：电脑得开着。

### B. 真 App 图标 —— TrollStore（不需要开发者账号，不需要 Mac）

1. 把 `legado-ios/` 推到 GitHub 仓库
2. Actions → `build-unsigned-ipa` → Run workflow → 下载 `LegadoMobile-unsigned.ipa`
3. iPad 用 Apple ID 侧载 TrollInstallerX（需开发者模式 + 信任描述文件）
4. TrollStore → Settings → Install **ldid**（否则装第三方 IPA 会报 173）
5. IPA 传到 iPad，用 TrollStore 打开安装

TrollStore 支持 **14.0b2–16.6.1 / arm64**，iPad 6（A10，arm64）跑 16.3.1 正好在区间内，
走 TrollInstallerX 那条路。

### C. 有 Mac 或开发者账号

Xcode 打开 `ios/LegadoMobile.xcodeproj`，改 `PRODUCT_BUNDLE_IDENTIFIER`，签名即可。
或者 `xcodebuild -scheme LegadoMobile -destination 'generic/platform=iOS' build`。

## 八、没解决 / 需要你知道的

1. **没有 IPA 成品**。这台机器没有 macOS/Xcode，Swift 编译无法在本地完成或验证。
   我只做了语法与工程图两个层面的静态验证 —— 这能挡住大部分低级错误，
   **但不能替代真正的 `xcodebuild`**。CI 第一次跑仍有可能因 SDK/符号细节失败。

2. **服务要单独跑**。Node 服务运行在电脑上；App 本身不含 Node 运行时。
   想做到"iPad 全离线自足"，需要把服务重写成 Swift 内嵌（我留了 `WebApp/` 本地壳和
   `/api/health` 探测，但没做 Swift 版 HTTP 客户端 + 规则引擎）。

3. **不是 100% 兼容所有书源**。实测 22 个真实书源里 1 个完全跑通；
   已实现的是规则引擎主干，缺少的部分会**明确抛错**而不是静默返回错数据：
   - `@webjs:` / `java.startBrowserAwait`（需要内嵌 WebView 渲染，3/22 个源依赖它）
   - `java.queryTTF`（字体反爬）
   - `Packages.*` 只暴露了极少数类
   - 需要登录 / 验证码的书源（`loginUrl` / `loginCheckJs` 未接入）
4. **没有真机验证过**。我没有 iPad，所有验证都在本机（Windows + jsdom + 静态检查）。
   "能在 iPad 6 上安装并打开"这一步必须在你的设备上完成。

5. **UI 只在 DOM 层面验证**。Chromium 在这个沙箱里起不来（mojo 被拒），
   所以没有真实渲染截图，字体/间距的实际观感需要你在 iPad 上看第一眼。

6. **合规提醒**。上游因版权问题被清空、作者已获刑。书源是用户自备内容规则，
   但请自行确认你导入的书源与阅读内容的合法性。
